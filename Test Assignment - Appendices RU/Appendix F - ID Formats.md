# Форматы идентификаторов и ключи джойнов

*Перевод. Оригинал: [../Test Assignment - Appendices/Appendix F - ID Formats.md](../Test%20Assignment%20-%20Appendices/Appendix%20F%20-%20ID%20Formats.md)*

## Основные идентификаторы

| ID | Формат | Источник | Примечания |
|----|--------|--------|-------|
| `account_id` | UUID | `ods.pc_kernel.ACCOUNT` | Универсальный идентификатор счёта. Присутствует почти во всех таблицах DM. |
| `client_id` | UUID | `ods.pc_kernel.ACCOUNT` | У одного клиента может быть несколько счетов (CC + PL + GRZD). |
| `application_id` | UUID | `dm.applications` | По одному на кредитную заявку. |
| `statement_id` | Integer | `ods.pf_engine.STATEMENTS` | Идентификатор биллинговой выписки по CC. |
| `statement_num` | Integer | Вычисляемый | Порядковый номер выписки внутри счёта (1, 2, 3...). |

## Типовые паттерны джойнов

**Таблицы дневной гранулярности** (большинство таблиц DM): джойн по `account_id` + `report_date`.

**Таблицы на уровне выписки** (специфично для CC): джойн по `account_id` + `statement_num`.

**Обогащение из мастера счетов**: джойн любой таблицы к `dm.accounts` по `account_id`, чтобы получить `product_risks`, `account_state`, дату выдачи и т.д.

**Агрегация на уровне клиента**: джойн через `dm.accounts.client_id` для агрегации по всем продуктам клиента.

## Межсхемные джойны

| Откуда | Куда | Ключ джойна | Сценарий |
|------|----|----------|----------|
| `dm.*` | `dm.accounts` | `account_id` | Добавить тип продукта, состояние счёта |
| `dm.*` | `ods.user_mgmt.USER_DATA` | `client_id` | Добавить демографию (пол, возраст, штат) |
| `dm.applications` | `dm.scoring_log` | `application_id` | Добавить детали скоринга |
| `dm.stm_cc` | `ods.pf_engine.STATEMENTS` | `statement_id` | Добавить сырые атрибуты выписки |
| `dm.*` | `ods.pc_tariffs.TARIFFS_ACCOUNTS` | `account_id` | Добавить информацию о тарифе/ценообразовании |

## Ловушки

- `account_id` имеет формат UUID — в SQL всегда в кавычках (`WHERE account_id = '...'`)
- Некоторые таблицы ODS называют одну и ту же сущность по-разному (например, `id` вместо `account_id`)
- `report_date` в таблицах DM имеет тип date (без времени), но в ODS встречаются таймстампы
- При джойне DM к ODS учитывайте разницу часовых поясов (DM — Мехико, ODS может быть в UTC)

## Дополнительные паттерны джойнов

### Origination против CLIP в limit actions

Чтобы отличить лимиты выдачи от событий CLIP, джойните `dm.limit_actions` к `dm.utilizations` по `account_id`, затем применяйте: `bs_day <= utilization_date + 100` = origination, `> 100` = CLIP.

### Таблицы на уровне выписки — только будни

Таблицы, где датой служит `end_date` (stm_cc, stm_grzd, stm_cor_cc, clip_statements, npv_naive_details), содержат только даты рабочих дней (пн–пт). Если ожидать выходных дат, данные всегда будут выглядеть устаревшими.

### Агрегация COR%

При агрегации COR% всегда фильтруйте `statement_num >= 2`. У выписки 1 COR нулевой (просрочить ещё нечего), что размывает отношение. Аннуализируйте через `* 12`, а НЕ взвешиванием по дням.
