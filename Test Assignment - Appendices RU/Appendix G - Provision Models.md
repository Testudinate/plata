## Поколения моделей управленческих резервов

Plata параллельно эксплуатирует несколько поколений моделей управленческих резервов. Все работают с **основным долгом** (не с процентами).

### Сравнение Gen2 и Gen3

| Аспект | Gen2 | Gen3 |
|--------|------|------|
| Статус | Официальная / продовая | Модель нового поколения, набирает распространение |
| Сценарий использования | Кросс-юнитовые KPI, управленческая отчётность | KPI, специфичные для коллекшена |
| Семейство методологии | В стиле loss-given-default | В стиле hazard / миграционных матриц |
| Месячные результаты | Очень близки к Gen3 | Лучше для гранулярного анализа коллекшена |
| Декомпозиция COR | `cor_total = cor_0_bucket + cor_dlq_fact` | `cor = cor_1p_fact + cor_collection_fact` |

**Что когда использовать**: Gen2 — для KPI, общих между подразделениями (Total CoR портфеля, управленческая отчётность). Gen3 — для KPI коллекшена (CoR после 1 DPD, коллекшн против прогноза).

### Философия COR (управленческие резервы)

В «идеальном» состоянии ВЕСЬ управленческий COR приходит из: (1) миграции 0 → 1+ DPD (inflow) и (2) роста портфеля с 0 DPD. Любой ненулевой `cor_collection_fact` сигнализирует, что коллекшн отрабатывает хуже модели.

## Модель Gen5 (NPV)

Модель чистой приведённой стоимости на уровне счёта, используется для анализа прибыльности и решений по CLIP.

- **Gen5v1** = текущая продовая модель. Предыдущая: Gen5v0.
- В качестве «долгосрочной» / «lifetime» точки отсчёта используется отсечка по поздней выписке.
- **NPV Portfolio** = ORIG + ORIG_CLIP. Для старых винтажей: ORIG gen5 + ORIG_CLIP gen4. Для новых винтажей: полностью gen5.

### Продовые таблицы

| Таблица | Гранулярность | Размер | Описание |
|-------|-------|------|-------------|
| `dm.NPV_GEN5_DETAILS` | счёт x выписка | Большая таблица предсказаний уровня выписки | Предсказания на уровне выписки |
| `dm.NPV_GEN5_AGG` | счёт | Агрегация на уровне счёта | Агрегация PV на уровне счёта |

### Устарело: NPV_GEN5_PV_DETAILS

`NPV_GEN5_PV_DETAILS` была **удалена** в ходе недавнего рефакторинга. Содержавшиеся в ней колонки (`active_clients_predict`, `opex_predict`, `funding_predict`, `debt_funding_share`) перенесены в `NPV_GEN5_DETAILS`. Любые запросы, ссылающиеся на `PV_DETAILS`, нужно переписать на `DETAILS`.

### Расчёт EL LT (Expected Loss Lifetime)

Две эквивалентные формулы аннуализированного COR за срок жизни:

Из PV_AGG:
```sql
SELECT SUM(cor_total_predict_lt) / SUM(bal_total_predict_lt) * 12 AS el_lt
FROM dm.npv_gen5_agg
WHERE ...
```

Из DETAILS на выписке-отсечке lifetime:
```sql
SELECT SUM(cor_orig_predict) / SUM(bal_orig_predict) * 12 AS el_lt
FROM dm.npv_gen5_details
WHERE statement_num = <lifetime_cutoff> AND ...
```

Обе дают одинаковый результат. Множитель `* 12` аннуализирует месячную ставку.

### Перерасчёт модели

Gen5v1 периодически переоценивается. Недавние рекалибровки существенно сдвинули EL LT для части исторических винтажных когорт. Учитывайте это при сравнении исторических снапшотов NPV.

## Расчёт резервов по процентам (MxGAAP)

Резервы MxGAAP покрывают общий EAD (основной долг + начисленные проценты). Разложение на проценты и основной долг на уровне счёта:

```
provision_rate = PROVISIONS / EAD
yield_prov = provision_rate × GINTEREST_BALANCE_MXGAAP_ADJ
prnp_prov = provision_rate × BALANCE_MXGAAP
```

Исходная таблица: `risk_prov.prov.MXGAAP_PROV_CC`. Полная документация таблицы — в `finance/mxgaap_provisions.md`.

Замечание: это относится только к резервам MxGAAP (регуляторным). Управленческие резервы (Gen2/Gen3) работают только с основным долгом.

## Конвейер скоринга

Скоринг заявки состоит из четырёх стадий, фиксируемых в `dm.SCORING_LOG`:

1. **Inner Scoring** (`innerscoring_*`): базовая проверка допуска (возраст, дубликаты, whitelist).
2. **Pre-Application Scoring** (`preapplicationscoring_*`): запрос в бюро, базовый скор.
3. **Application Scoring** (`applicationscoring_*`): полная оценка риска — PD-модели, фрод-скоры, политики.
4. **Final Scoring** (`finalscoring_*`): финальное решение, включая KYC, назначение лимита, верификацию дохода.

Ключевые поля скоров: `pd002`, `pd003`, `pd005`, `pg001` (payment generation), плюс внешние фрод-скоры.
