F. Observations that are not errors

  • Priority is not set by effect size. The rule "filter on statement_num >= 2" is repeated verbatim three times — in Appendices C, D and F. Measured on reproduced data, its contribution to the divergence between calculations is 0.05–0.24 pp, whereas the contribution of the grain choice is 2.1–2.7 pp — an order of magnitude larger, and mentioned nowhere. The warning is right, its weighting is not.
  • The interview notes contain speech-recognition artefacts and are not marked as a draft: "Axon EDC Disk Group", "diplomint coordinator", "Wisla/Voyager", "anpoints", "IChart, ISIT". Several employment periods are recorded as "unknown". To a human this is noise; to an LLM it is a source from which it will reproduce non-existent product names as fact. Such files should either be proofread or explicitly flagged as "machine transcript, not a source of truth".
  • Appendix I uses DMBoK loosely. It says "across the 11 DMBoK disciplines" and names Change Management and Data Catalog Management among the six tracked. DAMA DMBoK has eleven knowledge areas and neither of those is among them: the catalog falls under Metadata Management, change control under Data Governance. Reference and Master Data are one area in DMBoK and are split into two here. The assignment itself asks to "connect your proposals to DMBoK disciplines", so the terminology should either be aligned to the framework or honestly labelled as an in-house adaptation.

What dbt does not close: contradictions between prose documents, subject-matter errors in reference data, and anything outside the model graph. That remainder is exactly what the agent is for.

What the validator agent should look like

The key requirement: the validator is a separate role from the analyst. They have different jobs, different privileges and a different cost of error. The analyst answers questions and should be cautious; the validator hunts for discrepancies and should be pedantic.

  1. Inputs: the documentation, INFORMATION_SCHEMA, the catalog, the change log and test results. Not text alone — otherwise there is nothing to reconcile against.
  2. Four explicit tasks instead of a generic "check this": (1) execute every code example; (2) reconcile every object and column mentioned against reality; (3) find statements about the same object that contradict each other; (4) flag unstated assumptions.
  3. Output: findings with file, line and quote — as in this document. Without a quote a finding is unverifiable and will be ignored.
  4. Human triage of false positives. A validator whose findings are not filtered teaches the team to ignore it within two weeks — exactly like the Monday false freshness alarm.
  5. The validator has its own golden set. Otherwise there is no one to validate the validator: feed it a document with twenty known defects and see how many it finds. This document is a ready-made set — twenty labelled findings with answers.
What I would put into CI in the first week. Ordered by benefit-to-effort, not by completeness.
1. Execution of every code example from the documentation against reference data. Cheapest of all, and it catches the most dangerous class — "copied from the document and got the wrong number".
2. Reconciliation of documented names against INFORMATION_SCHEMA. Catches A2, A4, B1, B4 and C4 with a single test.
3. DDL snapshot and reconciliation against the change log — already built and working.
4. LLM review for contradictions — weekly on a schedule rather than on every commit: it is the most expensive and the noisiest detector.

What I propose to do with the appendices themselves

Do not edit them. The appendices were issued as the terms of the assignment, and editing the terms to fit one's own implementation is a substitution. The right order is:

  1. The eight critical findings (A1, A2, A3, B1, B5, C2, D2, E2) go into tickets raised against the documentation owner, with quotes — that is first-week work, not a matter for debate.
  2. The negative COR% in Appendix C and the sign confusion in the t-statistic should be fixed first: they produce a wrong number silently.
  3. The holiday calendar should be reconciled with the official CNBV source and moved from a hand-written list to a load.
  4. The interview notes should be marked as a machine transcript — one line in the file header, against a high cost of error if an agent reads them.
